# 第 16 章：方法论

前面十五章讲的是具体问题和具体工具，本章讲的是它们背后的共同动作：一次性能调查到底是怎么从"用户说卡"走到"修复并验证"的。

工具可以查文档，方法论只能靠练。但练习如果有章法，成长会快得多。实际工作中大量性能调查失败的方式惊人地一致：现象没定义清楚就动手抓数据（抓了十份 Trace 却不知道要验证什么）；把相关性当因果（"卡顿和 GC 同时出现，所以是 GC 的锅"）；改完不看数据就收工（感觉快了，实际指标没动）；报告里只有结论没有证据链，三个月后没人能复查。这些失败和工具熟练度无关，是流程问题。

本章 16.1 节给出四步框架：**现象定义 → 证据边界 → 假设与验证 → 修复与回归**。它提炼自前面各章反复出现的动作——第 7 章丢帧分析先框选区段定量再定界，第 8 章时延分析先钉死起止点，第 9 章 AppFreeze 先读 Reason 再选读法——这些其实都是同一个方法在不同问题上的实例化。这一节还会讨论四类证据形态（Trace、日志、Profiling、复现条件）各自能证明什么、不能证明什么，最后给出一个可复查的调查报告模板。

阅读上有个建议：这一节不要按顺序一次读完就放下。第一遍在读完第二部分之后看，重点看四步框架，把它和刚读过的案例对应起来；第二遍在自己做完一两次真实调查之后看，重点看证据边界那一节——几乎每次复盘都会发现，当时卡壳的地方不是工具不会用，而是对某份证据寄予了它承受不了的信任。报告模板则建议直接拷走，从下一次调查就开始用，写得多了自然知道哪些字段可以省、哪些一次都不能省。

这是全书最短的一章，也是建议每隔一段时间重读的一章。工具会更新换代，定义问题、约束证据、验证假设的纪律不会过时。掌握它之后，第三部分前面三章的工具知识才真正长成能力：hitrace 与 Profiler 决定我们能看到什么，方法论决定我们看到之后怎么想、怎么下结论。
