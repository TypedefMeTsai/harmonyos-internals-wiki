# 附录 F：鸿蒙性能学习路线

这条路线假设读者有移动开发经验（不限平台），目标是能独立完成鸿蒙应用的性能分析与优化。分三个阶段，每阶段给出目标、学习内容、动手任务和验收标准。章节号指本书目录。

## 阶段一：入门（会测、会看）

**目标**：建立性能的基本盘认知——知道帧是怎么渲染的、时延怎么算、工具怎么开。

**学习内容**：

- 第 1 章（系统架构全景）：Stage 模型与进程模型，知道应用的代码跑在哪个进程、谁把它拉起来。
- 第 2 章 2.1-2.2（渲染架构与 Vsync）：一帧的生命周期，App 侧与 RS 侧的分工。
- 第 13 章 13.1（hitrace 命令与 tag）：会抓一份基础 Trace。
- 第 14 章 14.1-14.2（Frame 与 Launch 会话）：会录一次丢帧和一次冷启动。
- 附录 B（hdc 命令）：连接、安装、日志、强制停止的常用命令用熟。

**动手任务**：

1. 用 `aa force-stop` + 桌面点击，给自己的应用测一次真冷启动，Launch 会话标出七个阶段。
2. 录一段列表滑动的 Frame 会话，找到至少一个红帧，说出它是 AppDeadlineMissed 还是 RenderDeadlineMissed。
3. 用 hitrace 命令抓 10 秒 Trace，找到自己应用的进程泳道。

**验收标准**：不查文档能完成上述三项；能解释"1100ms"和"600ms"两个启动口径的区别。

## 阶段二：进阶（会分析、会优化）

**目标**：对丢帧、启动慢、内存大三类主战场问题，能走通"量化 → 定位 → 修复 → 验证"全流程。

**学习内容**：

- 第 7、8、9 章（流畅性、响应、AppFreeze）：故障模型与判定机制。
- 第 10 章 + 第 21 章（内存）：Snapshot 对比工作流。
- 第 19、20 章（启动优化、渲染优化实战）：全部清单逐条上手。
- 第 14 章 14.3（CPU/Memory/Snapshot 会话）：分析工具补全。

**动手任务**：

1. 给一个长列表页面做完整优化：LazyForEach + 复用 + 布局扁平化，前后对比丢帧率和 BuildLazyItem 耗时，记录数据。
2. 做一次启动优化冲刺：Launch 找最长阶段 → 按 19.2 清单治理 → AppAnalyzer 体检报告全绿。
3. 复现一个内存泄漏（故意写个订阅不取消），用 Snapshot 对比定位到代码行，再修掉。

**验收标准**：三个任务都有前后对比数据；能说出每条优化改变了渲染/启动链路的哪一环。

## 阶段三：深入（会推理、成体系）

**目标**：能处理跨进程、跨形态、线上环境的复杂问题，并建立团队级质量机制。

**学习内容**：

- 第 3、4、5 章（输入、内存管理、并发调度）：机制级理解，Trace 里能读懂系统侧行为。
- 第 11、12 章（功耗、网络）+ 第 23 章（功耗与包体积实战）：发热-卡顿循环、HWC 失效的完整推理。
- 第 17、18 章（OpenHarmony 系统优化、设备形态）：系统视角与多形态差异。
- 第 24 章（可观测性）：hiAppEvent + AGC 的线上质量体系。
- 第 16 章（方法论）：证据驱动的分析纪律。

**动手任务**：

1. 给一个视频页面排查"看久了发烫变卡"：从 Frame 会话查到 HWC 失效，给出视效改造方案并验证功耗回归。
2. 给应用搭最小线上质量看板：hiAppEvent 订阅崩溃/冻屏/启动耗时，定三条发布门禁。
3. 选一个折叠屏连续性缺陷（展开后滚动位置丢失），定位到状态存活问题并修复，用折叠-展开循环回归。

**验收标准**：能向团队完整讲解一次复杂问题的推理链（证据 → 假设 → 验证 → 结论）；产出的门禁规则在至少一个真实版本中执行过。

## 长期习惯

- 每个版本冻结性能基线数据（启动、帧率、内存、功耗），劣化必归因。
- 关注官方《应用性能体验建议》与最佳实践文档（bpta-* 系列）的更新，规范数值会随版本演进。
- 附录 C/D 打印在手边：Trace 点速查与分析 Checklist 是日常翻得最勤的两页。
